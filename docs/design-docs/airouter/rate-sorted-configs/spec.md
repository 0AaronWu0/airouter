# Feature: API 配置按倍率排序与最低倍率切换

**作者**: Codex  
**日期**: 2026-07-12  
**状态**: Quick Draft

---

## 1. 背景 (Background)
### 1.1 问题描述
当前 API 配置列表在当前配置之后仍按配置原始索引展示，没有按倍率从低到高排列，用户无法直观看到下一优先级配置。切换配置后列表顺序也不反映倍率优先级。

### 1.2 现状分析
- `chrome-popup-admin/popup.js:getVisibleConfigs()` 当前先将激活配置置顶，其余配置按 `index` 升序排列。
- `openai.js:selectApiModeAutoSwitchTarget()` 已在可用 API 配置中选择低于当前配置且倍率最低的配置；该逻辑不改变配置数组顺序。
- `openai.js:buildConfigAdminResponse()` 将运行态真实倍率覆盖到管理快照的 `item.rate`，前端可直接使用该值排序。

### 1.3 主要使用场景
- 用户打开 API 配置列表时，查看当前激活配置及其他配置的倍率优先级。
- 用户手动切换配置后，列表重新渲染，新的激活配置置顶，其余配置按倍率升序排列。
- API 自动切换时，优先选择可用且倍率最低的配置。

## 2. 目标 (Goals)
- 保持当前激活配置第一位，并将其余配置按倍率从低到高展示。
- 保持并验证自动切换选择可用最低倍率配置的行为。

### 2.1 非目标 (Non-Goals)
- 不改变 `openai.json` 中配置项的持久化顺序。
- 不改变真实倍率同步来源、同步周期或倍率值。
- 不调整 Token 配置的排序规则；Token 与 API Key 混合展示时仍遵循激活置顶后按类型过滤结果中的排序规则。

## 3. 需求细化 (Requirements)
### 3.1 功能性需求
- API Key 列表中，`is_active=true` 的配置始终排在第一位。
- 其余 API Key 配置按数值倍率升序排列。
- 没有有效倍率的 API Key 配置排在有倍率配置之后，并按原始 `index` 升序稳定排序。
- 倍率相同的配置按原始 `index` 升序稳定排序。
- 自动切换仅考虑可用、具有有效倍率且倍率低于当前配置的 API Key，并选择其中倍率最低者。
- 切换完成重新获取快照后，继续执行“激活置顶、其余按倍率升序”的展示规则。

### 3.2 非功能性需求
- 排序只影响前端展示，不改变后端配置数组和持久化文件。
- 保持现有筛选、激活标记和切换接口行为不变。
- 新增排序测试，现有测试全部通过。

## 4. 设计方案 (Design)
### 4.1 方案概览
在现有 `getVisibleConfigs()` 排序器中增加倍率比较：先比较激活状态，再比较有效倍率，最后比较原始索引。复用现有后端自动切换算法，仅补充回归测试。

### 4.2 核心逻辑实现
排序键顺序：`is_active`（激活优先）→ `item.rate`（有效倍率升序）→ `index`（稳定兜底）。倍率使用数值比较，避免字符串字典序导致 `0.1` 与 `0.04` 排序错误。

## 5. 测试计划 (Test Plan)
### 5.1 单元测试
- 静态检查前端排序逻辑包含激活优先、数值倍率升序和索引兜底。
- 保留并验证后端最低可用倍率自动切换测试。

## 6. 约束与假设
- 管理快照中的 `item.rate` 已包含真实运行态倍率时，按该值排序；未同步成功时按本地配置倍率排序。
- 本次以 Chrome Popup 管理页为排序实现入口；后端调度逻辑不需要行为改动。
